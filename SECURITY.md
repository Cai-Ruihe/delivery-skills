# Security policy

Reports should identify the affected commit, instruction or boundary, a safe minimal reproduction, and the observed versus expected behavior. The current public snapshot is the supported version.

Do not put credentials, private prompts, customer data, personal information or sensitive exploit details in public issues. If GitHub private vulnerability reporting is available, use that channel. Otherwise open an issue requesting a private contact channel without including sensitive details.

Relevant boundaries include unauthorized delegation or effects, prompt injection, multiple writers, ambiguous retries, false worker identity, and acceptance claims unsupported by the requested consumer evidence. Skills do not replace host permissions, sandboxing or human authority. Review and automated scans reduce exposure risk but cannot guarantee detection of all sensitive information.
