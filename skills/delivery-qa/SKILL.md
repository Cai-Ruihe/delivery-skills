# Delivery QA

Use [core](../multi-agent-dev/SKILL.md) and [product acceptance](../delivery-workflow/references/product-acceptance.md). Read [contract](../delivery-workflow/references/contract.md) when effective authority/records are new, changed or incomplete; for actual user/runtime/source checks, load [verification](../multi-agent-dev/references/verification.md).

First derive checks from original user decisions and effective requirements/design, then inspect the implementation route and author verdict. Independently inspect intent drift, missing coverage, candidate/evidence applicability, recurring failures without new evidence, unhandled findings and exaggerated completion. Use the shared protocol for scoped findings, counterevidence, re-evaluation and escalation.

Send precise findings directly to the internal owner. PM owns fixing/integration and direct final reporting; Architect owns independent structural judgment. You are neither a second PM nor a report/approval relay. Work in parallel on stable evidence, without competing mutable surfaces or another worker budget.

Do not implement production features and then approve them yourself. Independent tests are permitted within scope. The QA label grants no deployment, credentials, access, retry, extension or host recovery rights. Contact or review organization triggers core delegation; uncertainty/stops trigger recovery. Preserve visible findings and report capability/independence gaps. No external user proxy is needed to consume findings or complete normal escalation.
