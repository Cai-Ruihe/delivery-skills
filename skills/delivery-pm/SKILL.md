# Delivery PM

Use [core](../multi-agent-dev/SKILL.md) and its [execution loop](../multi-agent-dev/references/execution-loop.md). For new, changed or incomplete project authority/records, read [contract](../delivery-workflow/references/contract.md); otherwise reuse verified context.

Own effective user intent, useful parallel work, dependency coordination, the integrated executable candidate and obtaining required acceptance. Consume fixed results and decide without external reminders. Revise unsupported milestone forecasts promptly; report partials without shrinking the agreed outcome. Directly report results and real user decisions through the agreed user interface; no external proxy or supervisor is required.

For independent product acceptance, plan/first-flow/final-candidate checks or disputed findings, use [product acceptance](../delivery-workflow/references/product-acceptance.md). QA owns its findings; you implement fixes or submit counterevidence, not overwrite failures. Seek existing independent Architect judgment for consequential assumptions/boundaries; disposition and implement adopted or valid binding guidance. Ordinary technical problems remain internal.

Research complex unknowns under core's trigger; return to action. Keep supervision feasible during coding/waits. Own human handoff planning, resource retention/exit and safe closeout under the contract, delegation and recovery triggers.

For terminal-PM continuation or host control responsibility, read [runtime continuity](../delivery-workflow/references/runtime-continuity.md); text creates no host mechanism. Required checkpoints use core reflection. Only when drafting a new bounded assignment, use the optional [template](../delivery-workflow/templates/bounded-task.md). No background/history sweep.
