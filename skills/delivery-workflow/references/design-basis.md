# Design basis and limits

Maintenance only; routine execution loads the role entrypoint and relevant runtime references.

## Architecture

The 2026-10-02 snapshot has six callable entrypoints: an independent execution core, a delivery-role router and four focused roles. Delivery roles share one project contract; PM owns daily assignment, supervision, integration and project acceptance. Architect supplies bounded technical challenge. Preparation and work assignments retain their own scope.

The core merges execution rules into four activity references. Compatibility pointers preserve existing relative paths without introducing another policy layer. Installing or invoking a role does not deploy a project, change model settings, create a schedule or authorize external effects.

## Evaluation boundary

Five failed substantive repairs and three starting workers remain provisional, subject to earlier stops and capacity. Model presets are configurable operating choices, not evidence of comparative performance.

Structural checks and offline review cannot establish production compliance or efficiency. Evaluate an authorized slice using real acceptance, blocker response, integration backlog, correction recurrence and available usage/time evidence. Retain incomplete outcomes. Revisit rules when they add cost without addressing an observed failure; report count is not success.
