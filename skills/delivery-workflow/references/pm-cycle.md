# PM Daily Delivery Cycle

Read on project takeover or sustained PM work; reuse. PM is the daily assignment, monitoring, integration and acceptance owner. Root/Dot handles consequential exceptions or exact missing capabilities, not routine worker tracking.

## Start and actively assign

Recover the [contract](contract.md), owners, pending operations, baseline and applicable window/deadline. Choose a smallest complete consumer slice and first unproved boundary. Check feasibility before expanding coupled work.

At start/resumption, stable contract, newly ready independent work or released capacity, check dispatch opportunities. When independent progress, bounded scope, concrete deliverable/check, isolated writing, worthwhile benefit and authority hold, proactively assign; do not wait for root reminders. Use core [delegation](../../multi-agent-dev/references/delegation.md) for profiles, capacity, assignment and contact lifecycle. Keep unknown coupled producer/consumer work with one owner. Capacity and integration evidence govern expansion; initial worker counts are neither quotas nor permanent ceilings.

A task package contains the applicable scope/version, fixed input, owned surface, deliverable/check, dependency, deadline, authority and stop condition. Use native fields or one concise message.

## Respond and integrate

| Event | PM's next action |
|---|---|
| Completion/artifact ready | Inspect fixed artifact and actual checks; integrate and update acceptance |
| Blocker/dependency change | Locate responsible owner, inspect narrowly, assign a discriminating unblock or independent work |
| Interface drift/write conflict | Stop affected assignment, reconcile state/owners, restore one writer and stable boundary |
| Agreed node or critical-path stagnation | Check new evidence and previous correction; choose next acceptance-changing action |
| Integration backlog/repeated seam waiting | Pause expansion, reunite coupled work and prioritize integration |

PM may implement critical integration, inseparable seams or short repairs. Transfer prolonged independent implementation when it would leave workers unsupervised. Before long coding/waits, use supported bounded yield/waits, agreed checkpoints or a limited observer; retain PM responsibility. No permanent monitor or assumed background wakeup.

Own core [hourly reflection](../../multi-agent-dev/references/self-review.md) during sustained execution; preserve its actual checkpoint and apply accepted corrections to the next affected package/check. Do not duplicate that protocol or replace corrective execution with longer criticism.

## Escalate and stop safely

Material technical disputes, architectural defects or important recurrence after correction go to an authorized independent Architect with concrete evidence/question. Business decisions, missing authority or precise unavailable capabilities go to root/user. Ability support returns evidence to PM for integration. Ordinary empirical work stays assigned.

On user stop, material pivot or applicable expiry, promptly stop affected workers and new dispatch using supported controls. Verify worker terminal state and uncertain effects; preserve IDs. Until reconciled, do not retry, replace or resume conflicting work. Report each residual Unknown; PM stopping does not prove every worker stopped. Unaffected work continues only if original authority and stop wording permit. Missing controls are a precise blocker, never grounds to delete locks or force-kill.

Use core [recovery](../../multi-agent-dev/references/recovery.md). Accept actual requested consumer evidence or preserve partial outcome and next owner/action; no automatic extension or weakened acceptance.
