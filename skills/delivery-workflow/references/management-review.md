# User-appointed management review

Read only when the user has appointed a management-method reviewer for this project. The project record holds the appointment, reviewer thread/host/model, authorized communication route and duration. Do not infer one for unrelated projects or create another resident role.

PM remains responsible for delivery, integration, acceptance and direct reporting. Architect owns technical structure; QA owns candidate findings. The management reviewer examines how decisions, roles, Skills and human participation affect outcomes. It is not a second PM, routine code approver or host recovery service. Advice creates no new authority or global HOLD.

A round is the user's bounded development work package/window, not every agent turn or commit. At round planning/start, PM submits the effective outcome/exclusions, original decisions and current grants/bounds, fixed baseline, previous lessons and trial status, key assumptions, real acceptance method, owners and pending effects. Request review through the appointed supported route. Do not wait for a formal ACK or new sign-off unless a controlling user decision actually requires it; apply real authority conflicts under existing recovery rules.

At completion, stop, expiry or handoff, stop affected work on time and submit actual user outcomes, fixed evidence, local/deployed/unverified distinctions, failures, route deviations, rework, human interventions, Skills version/loading/compliance evidence, resources and unresolved effects. This reporting obligation never extends development. Preserve it in existing round records if sending fails or PM terminates before submission; do not invent reliable host wakeup.

The end review must explain effective/failed management mechanisms with evidence; separate Skill content, loading, compliance and outcome; distinguish human new information, technical judgment, trade-offs, authority and repeated correction; compare relevant projects while recording scope/stage/model/tool/permission/infrastructure confounders; resolve prior improvement trials and propose few next checks with retain/withdraw conditions. Use the approved round scope, not hindsight-expanded ambitions. Missing or unrun trials remain Unknown, not failure. Produce readable user-facing reflection, not only status or files.

For an adopted guarded round, retain an end-review obligation in the existing round record and reconcile it at closeout, including after the work deadline. A missing result is pending, not completion; this grants reporting/cleanup only, never more product execution. Before PM exit with an outstanding result, name the existing authorized continuation owner or verified bounded follow-up in the round record; a pending field alone transfers no responsibility. When ready, return the fixed result through that supported route once, preserving uncertain delivery. Do not keep workers idle for an ACK or restart product work to settle feedback.

Use existing records and pointers, not a second PRD or mandatory schema. Track a logical project/round/phase/material-version request and its receipt/result; accepted is not completed. Reconcile uncertain sends through supported reads before any resend. Reviewer feedback is not another round trigger. PM dispositions findings; substantive method/Skills changes require their actual authority or an explicit controlled trial, rather than automatic global rollout. Daily authorized review needs no repeated permission. No scheduler, communication guarantee, extra budget or development window is supplied by this reference.
