# Verify the requested capability

Read for real dependencies, consequential integration or staged delivery. A simple local edit needs its relevant check, not a release process.

Recover normal entry, established build/import/release route, last verified result, exact target and required identity. Inspect relevant approved records/artifact stores before declaring capability absent or using an old checkout. Check the route-threatening runtime/access/input contract early through approved interfaces; do not inspect unrelated secrets.

Build the smallest complete slice from actual input through required persistence and consumer/parent acceptance. A blocked real route may still permit isolated checks, but fixtures cannot establish provider readiness. Preserve the full outcome while reporting accepted partial work. Bind evidence to actual revision, configuration, package/data version, target, identity and operation; reuse only while freshness and assumptions hold.

Use the real parser/validator/consumer and retained unmodified inputs. Mock transport/effects without copying the implementation's assumptions. Relevant failures include atomicity, partial/empty inputs, authorization, persistence, idempotency and unrelated-data preservation. Inspect source/output semantics when generation is in scope; credentials or schema-valid bytes prove neither meaning nor generation. Archive metadata/integrity still matter when generation is excluded.

Distinguish collection, publication, import and consumption, with coverage/timestamps. Missing/stale/partial is not zero or fresh. Check whether required historical cutoff/completeness exists; only the requirement owner may change its meaning. Reuse compatible existing export paths; isolate real runtime/parser repair rather than redeploying every refresh.

Apply only stages required by scope: local candidate, authorized installation, hosted preflight, persistence/publication, consumer and native parent acceptance. Installed-code checks follow authorized installation; impossible gate ordering requires a ruling from its authority, not relabeling fixtures. Follow the existing target controller and [recovery](recovery.md) for effect authority/ambiguity. For fragile temporary operations, validate harmless commands/cleanup in the same runtime where practical, preserving actual expiry and readback.

UI claims require rendered consumption with required identity; API checks prove their serving path. Worker PASS/build/hash/deployment do not close a production request. Local assignments may finish locally. Use deterministic checks for mechanical work; consequential weakly verifiable changes warrant authorized non-author challenge. Review a stable slice and affected regressions; broaden only for new changes/failures. Findings need trigger, location, requirement and consequence, not a quota. Missing acceptance remains Unknown and open.
