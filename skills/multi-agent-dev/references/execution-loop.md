# One execution loop

Read for substantial/ongoing work, multiple dependencies or coordination. Clear small local tasks need only the core entry and relevant check. This is the sole execution-loop body; PM and assigned work add role responsibilities without another cycle.

At takeover, changed instructions/results/interfaces, ready work, blocker or integration backlog:

1. **Observe:** confirm current outcome/scope, baseline, owners, authority/bounds and pending operations using minimal native evidence. Reuse only demonstrably unchanged state. Inspect changed results and the first unproved capability boundary; distinguish callable, fixture, uninstalled, incompatible and unavailable authorized route.
2. **Choose:** select an acceptance-changing action or route-threatening assumption to discriminate. Check runtime/access/reader feasibility before dependent expansion. Diagnose before repairing. Legal pauses and useful architecture investigation are not failed execution.
3. **Act:** perform a bounded check/repair, dispatch useful independent work, research complex uncertainty, seek independent technical judgment, or present the smallest actual consequential gap to its owner. Do not wait for root to manage ordinary actions.
4. **Integrate/verify:** inspect fixed artifacts, integrate through their owner, test the changed boundary and previous correction. Update existing state with actual result, next owner/action and pass/stop condition. Partial remains partial.

For research read [research](research.md); for coordination/dispatch/contact/review read [delegation](delegation.md); consequential real seams use [verification](verification.md); disputed authority, failures, unknown operations and stops use [recovery](recovery.md). These links are conditional, not an automatic sequence. Keep supervision feasible during long coding/waits; no unsupported wakeup promise. Do not duplicate records, weaken acceptance or reset accumulated limits.
