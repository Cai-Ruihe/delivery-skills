5. Host-continuation detail moves out of the PM's ordinary entry. Confirmed ownership, serialized admission, races, active writers, unknown sends and original cumulative bounds retain their limits; text creates no scheduler or recovery service.
6. Existing philosophy, simpler-architecture method, bounded research, recovery and reflection bodies are retained. Independent Architect judgment, required three-hour checkpoints, model defaults, existing UI policy, MIT and safety boundaries remain. Verified new collection may legitimately return unchanged content; source-operation evidence establishes freshness.
7. Maintenance uses available owner-designated history without making any private file a runtime dependency. Private histories and all related internal/evaluation artifacts are excluded from this public package.

## delivery-skills-2026-10-10-r1

This revision replaces and consolidates existing guidance across the same six entries and nine references. It adds no runtime file, role, reporting service or approval layer.

1. Progress means an advance in the requested capability or evidence that changes a critical decision. The execution loop selects the first unproved real dependency, with proportionate risk, reversibility and lifecycle cost. Necessary preparation and lawful architecture pauses remain valid partial work.
2. PM owns the integrated executable version, useful parallel dispatch, result consumption and honest milestones. Implementation needs a receivable contract and integration capacity; bounded investigation may establish an unknown interface. Final acceptance checks the actual entry, package/runtime and known correction together before claiming consumer success.
3. Contact guidance distinguishes a draft, transport acceptance, acknowledgment, consent and result. Plan a realistic decision opportunity, disclose current execution gaps and never count unverified delivery or reply wall time as net project delay. Unknown delivery does not authorize automatic resend; late consent does not revive expired authority.

5. Development stop is not billing stop. Estimates are not invoices; unchanged grants need no repetitive approval, and missing shutdown authority requires the smallest actual decision.

Existing authority, tool-retry, uncertain-result, temporary-operation, stop and cleanup mechanics remain in their original references. ## delivery-skills-2026-10-04

This release reorganizes rule ownership and execution rather than appending a second workflow.

1. Shared philosophy distinguishes values, revisable empirical defaults and procedures; unfamiliar cases use explicit intent, evidence and reversible checks.
2. One execution loop supports PM autonomy: observe the current boundary, choose a useful action, act, integrate and verify. Bounded research must change the next decision or expose a precise gap, then return to delivery.
3. Architect forms an independent high-level view and returns executable trade-offs. Root-cause diagnosis compares local repair, boundary consolidation and mechanism replacement; elegance is not fewer lines or more abstraction. Emergency patches have observable repayment triggers.
4. The smallest real end-to-end slice checks risky runtime/access/reader boundaries early. Worker or local PASS proves only its actual scope; fixtures do not establish a real consumer outcome.
5. Parallel work requires independent contracts, isolated write surfaces and accountable integration. Zero workers is valid; coupled uncertainties stay with one owner.
6. Existing grants are reused for ordinary authorized actions. Official provenance does not expand permission. Old messages, busy writers, unknown operations and lawful stops are reconciled without automatic duplicate effects or resumption.
7. Short entries navigate conditional references. The old PM cycle and other superseded references are retired, leaving one body per shared rule. Reflection checks whether the previous correction changed the next action rather than producing another essay.
